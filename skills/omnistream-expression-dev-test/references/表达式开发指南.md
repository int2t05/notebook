# 第一部分:全链路与分类

## 1. 端到端架构总览

一条新表达式从 Flink SQL 到 Native C++ 执行,有两个互补视角:数据流视角(表达式对象如何流转)与生命周期视角(开发/运行各阶段落在哪个组件)。

### 1.1 数据流视角

```
用户 SQL (Flink SQL)
  ↓  Calcite SQL 解析 & 优化
OmniAdaptor 端生成 JSON 表达式协议
  ↓  RPC / 序列化
OmniStream 接收 JSON 表达式
  ↓  JSONParser::ParseJSON() 反序列化
Expr 树 (expression/expressions.h)
  ↓  ExprVerifier 验证语义
验证通过
  ↓  CodeGen (JIT / LLVM)
LLVM IR → 本地机器码
  ↓  执行
VectorBatch 数据处理
```

### 1.2 生命周期视角(5 阶段)

```
┌──────────────────────────────────────────────────────────────┐
│ 阶段1: 规划期 (Java, Client端)                               │
│   OmniAdaptor / RexNodeUtil.java                              │
│   识别表达式 → 翻译为 JSON AST                                │
│   ValidateCalcOPStrategy 白名单校验                           │
├──────────────────────────────────────────────────────────────┤
│ 阶段2: 部署期 (Java, Client端)                               │
│   OmniOperatorChain / CommonExecCalc                          │
│   JSON AST 嵌入算子链 → 序列化到 JobGraph                    │
├──────────────────────────────────────────────────────────────┤
│ 阶段3: 解析期 (C++, TaskManager端)                           │
│   OmniStream / StreamCalcBatch                                │
│   JSON 描述 → JSONParser → Expr 树                           │
├──────────────────────────────────────────────────────────────┤
│ 阶段4: 编译期 (C++, OmniOperator)                            │
│   ExpressionEvaluator → LLVM CodeGen                          │
│   Expr 树 → LLVM IR → Native 函数指针                        │
├──────────────────────────────────────────────────────────────┤
│ 阶段5: 运行期 (C++, OmniOperator + OmniStream)               │
│   FilterFunc / ProjFunc 批量向量化执行                        │
│   结果写回 VectorBatch                                        │
└──────────────────────────────────────────────────────────────┘
```

每个阶段对应不同组件的不同文件,开发一个完整表达式需要修改 **1-5 个文件**(视类型:Type D 1 个 / Type A·B 3 个 / Type C 4-5 个)。

### 1.3 各模块职责

| 层次                      | 模块           | 职责                                                        |
| ------------------------- | -------------- | ----------------------------------------------------------- |
| **OmniAdaptor 层**  | Calcite        | SQL 解析、校验、优化,生成表达式 JSON 协议                   |
| **OmniStream 层**   | StreamCalc     | 接收表达式,编排计算(行处理 + 批处理)                        |
| **OmniOperator 层** | expression/    | Expr 类体系、JSON 反序列化、Visitor 模式                    |
| **OmniOperator 层** | codegen/       | Function 注册、C 函数实现、JIT 编译(row JIT 路径)           |
| **OmniOperator 层** | vectorization/ | 向量化函数库(SimpleFunction/VectorFunction,150+ Spark 函数) |
| **OmniOperator 层** | type/          | 类型系统定义                                                |

## 2. 表达式开发分类

根据 Flink SQL 语义和 Omni 内部实现方式,新表达式分为四种类型:

| 类型             | 触发词   | JSON exprType | 改动范围                               | 典型示例                                                    |
| ---------------- | -------- | ------------- | -------------------------------------- | ----------------------------------------------------------- |
| **Type A** | 标量函数 | `FUNCTION`  | OmniAdaptor + OmniOperator             | `REVERSE`, `REPEAT`, `MD5`                            |
| **Type B** | 特殊语法 | 自定义        | OmniAdaptor + OmniOperator(jsonparser) | `NULLIF`(IFNULL 实际走 Type D 别名,见 §7.2)                                      |
| **Type C** | 聚合函数 | 算子级        | OmniAdaptor + OmniStream + OmniOperator     | `STDDEV_POP`, `PERCENTILE`                              |
| **Type D** | SQL 变体 | `FUNCTION`  | 仅 OmniAdaptor                         | `UPPER`→`upper`, `CHARACTER_LENGTH`→`char_length` |

```
            Type D                    Type A                    Type C
      (仅改名/翻译)             (标量函数+C++实现)          (聚合函数+算子)
     ┌─────────────┐          ┌─────────────────┐        ┌─────────────────┐
     │ RexNodeUtil │          │  RexNodeUtil     │        │  StreamExec*    │
     │    .java    │          │    .java          │        │    .java        │
     └──────┬──────┘          └───────┬───────────┘        └───────┬─────────┘
            │                         │                            │
            v                         v                            v
     JSON: FUNCTION             JSON: FUNCTION              JSON: aggInfoList
     function_name="upper"      function_name="reverse"     (算子级描述)
            │                         │                            │
            v                         v                            v
     JSONParser                 JSONParser                  StreamOperator
     → FuncExpr                 → FuncExpr                  Factory
     → FunctionRegistry         → FunctionRegistry          → OmniOperator
     → 已有upper()              → 需新增reverse()           聚合Operator
```

### 2.1 Type A 的两条子路径(关键决策)

Type A 标量函数在 OmniOperator 侧有**两条注册路径**,JSON 侧(`RexNodeUtil`)完全一样(都发 `FUNCTION` + `function_name`),区别只在 OmniOperator 注册到哪张表:

| 子路径            | 适用场景                                 | 实现位置                                                 | 注册位置                                              | 标杆示例                        |
| ----------------- | ---------------------------------------- | -------------------------------------------------------- | ----------------------------------------------------- | ------------------------------- |
| **向量化**(默认) | 纯列式可向量化、追求吞吐(90%+ 函数)   | `core/src/vectorization/functions/<Name>.{h,cpp}`      | `core/src/vectorization/registration/Register*.cpp` | `char_length`、`left/right`、`concat` |
| **row JIT** | 逐行复杂逻辑/外部库/特殊类型(json_value+JSON 缓存、md5/murmur/xxhash、布隆过滤器、Decimal 高精度、字典向量、UDF;及 BatchAdd/BatchLessThan 等批原语) | `core/src/codegen/functions/<domain>functions.{h,cpp}` | `core/src/codegen/func_registry_<domain>.cpp`       | `json_value`(本指南 §8)、`md5` |

> **选型规律**:新函数**默认走向量化**(SimpleFunction 简单逐元素 / VectorFunction 批级循环+变长输出+缓存);row JIT 是少数例外(外部库/有状态 row 级 C 函数、特殊类型底层算术、UDF、批原语)。**复杂度不是判据**——正则很复杂但用向量化机制承载(`SimilarFunction`——实属 Type B-② 见 §2.2,用 VectorFunction+线程级缓存),json_value 很复杂但走 row JIT;判据是**执行模型适配**:fit 批模型→向量化,需 row 级 C+外部库/特殊类型→row JIT。同域也会分叉(简单 JSON `GetJsonObject`/`FromJson` 向量化,复杂 `json_value` row JIT)。同一函数可能两边都有(如 `REVERSE`),新开发默认向量化。

> ⚠️ 本指南 §4 的 `REVERSE` 示例与 §8 的 `json_value` 示例均属 **row JIT 路径**(使用 `codegen/functions/` + `func_registry_*.cpp`,`Function` 构造注册)。**向量化路径**(SimpleFunction/VectorFunction + `Register*.cpp`)的完整开发流程见 `omnioperator-expression-dev` skill,其 C 函数规范不同(`call()`/`callNullable()` 返回 `Status`/`bool`/`void`,由向量框架处理 null,而非本指南 §12 的 row JIT 三元组规范)。开发前先判定走哪条路径。

### 2.2 Type B 的两种执行策略(重要)

Type B(特殊语法,自定义 exprType + 新 Expr 节点)在 OmniOperator 侧按"语义能否拆成已有向量化原语"分两种执行策略:

| 策略 | 判据 | 新向量化函数 | codegen `Visit` | ExprEval `Visit` | 执行路径 | 标杆 |
| --- | --- | --- | --- | --- | --- | --- |
| **B-① codegen 下放借原语** | 语义可拆(如 `<= AND <=`) | ❌ | lower 到原语(活) | 空 stub | codegen | BETWEEN |
| **B-② 专用函数 + 解释器** | 语义需专属逻辑(如正则) | ✅ `VectorFunction` | 返回 invalid(stub) | 调 `Apply`(活) | ExprEval | SIMILAR TO |

> 决策判据与完整文件清单见 [`表达式开发路径选择-向量化函数vs-codegen.md`](表达式开发路径选择-向量化函数vs-codegen.md)(其「范式 B/C」即本节 B-①/B-②)。⚠️ 两种策略都新建 Expr 类 → ABI 破坏,需 `omnistream_incr` 重编 OmniStream。

# 第二部分:框架核心原理

## 3. Expression 框架核心

### 3.1 Expr 类体系

所有表达式类型定义在 `OmniOperator/core/src/expression/expressions.h` 中,命名空间 `omniruntime::expressions`:

```
Expr (抽象基类)
  ├── DataTypePtr dataType          // 返回值类型
  ├── virtual GetType() -> ExprType
  └── virtual Accept(ExprVisitor&) = 0

  ├── LiteralExpr                   // 常量(int/bool/string/decimal 等)
  │     isNull, boolVal, intVal, longVal, doubleVal, stringVal...
  │
  ├── FieldExpr                     // 列引用
  │     colVal (列的索引)
  │
  ├── BinaryExpr                    // 二元运算:+, -, *, /, AND, OR, EQ, LT...
  │     op (Operator 枚举), left, right
  │
  ├── UnaryExpr                     // 一元运算:NOT
  │     op, exp
  │
  ├── InExpr                        // SQL IN
  │     arguments vector
  │
  ├── BetweenExpr                   // SQL BETWEEN
  │     value, lowerBound, upperBound
  │
  ├── IfExpr                        // SQL CASE/IF
  │     condition, trueExpr, falseExpr
  │
  ├── SwitchExpr                    // SQL 搜索 CASE(多个 WHEN)
  │     whenClauses, falseExpr
  │
  ├── CoalesceExpr                  // SQL COALESCE
  │     value1, value2
  │
  ├── IsNullExpr                    // IS NULL
  │     value
  │
  └── FuncExpr                      // 函数调用(内置函数或 UDF)
        funcName, arguments, function 指针, functionType
```

`ExprType` 枚举映射了所有表达式类型:

```cpp
enum class ExprType {
    LITERAL_E, FIELD_E, BINARY_E, UNARY_E, IN_E,
    BETWEEN_E, IF_E, SWITCH_E, COALESCE_E, IS_NULL_E,
    FUNC_E, INVALID_E,
};
```

**`json_value`、`REVERSE` 等函数调用都属于 `FUNC_E` 类型。**

### 3.2 Visitor 模式

`ExprVisitor` 接口定义了每种 Expr 类型的 Visit 方法,两个核心实现:

- **ExprPrinter** — 将表达式树打印为可读字符串
- **ExprVerifier** — 校验表达式语义(类型兼容性等),设置 `supportedFlag`

```cpp
class ExprVisitor {
public:
    virtual void Visit(const LiteralExpr&) = 0;
    virtual void Visit(const FieldExpr&) = 0;
    virtual void Visit(const BinaryExpr&) = 0;
    virtual void Visit(const FuncExpr&) = 0;
    // ... 每个具体 Expr 类型的 Visit 方法
};
```

### 3.3 JSON 序列化协议

JSON 到 Expr 的反序列化入口是 `JSONParser::ParseJSON()`:

```cpp
// jsonparser.cpp — 根据 exprType 分发
if (exprTypeStr == "FIELD_REFERENCE") ParseJSONFieldRef(jsonExpr);
else if (exprTypeStr == "LITERAL")    ParseJSONLiteral(jsonExpr);
else if (exprTypeStr == "BINARY")     ParseJSONBinary(jsonExpr);
else if (exprTypeStr == "FUNC" || exprTypeStr == "FUNCTION") ParseJSONFunc(jsonExpr);
else if (exprTypeStr == "SWITCH")     ParseJSONSwitch(jsonExpr);
// ...
```

每个 JSON 表达式对象的通用字段:

```json
{
    "exprType": "FUNC",             // 表达式类型(必需)
    "function_name": "json_value",  // 函数名(FUNC 类型必需)
    "returnType": 15,               // DataTypeId 枚举值(必需)
    "arguments": [...],             // 参数列表
    "width": 2147483647,            // VARCHAR/CHAR 宽度
    "precision": 0,                 // DECIMAL 精度
    "scale": 0                      // DECIMAL 刻度
}
```

`DataTypeId` 枚举见 [§11 数据类型映射](#11-数据类型映射)。

### 3.4 FuncExpr 的特殊处理

`FuncExpr` 是函数调用的载体。`ParseJSONFunc()` 的执行流程:

1. 解析 `function_name` 和 `returnType`
2. 构建参数列表 `vector<Expr*> args`
   - 对普通函数:直接解析 `jsonExpr["arguments"]`
   - 对 `json_value` 等特殊函数:调用专用参数构建函数
3. 根据返回类型构造 `DataType`(字符串类需要 width,DECIMAL 类需要 precision/scale)
4. 通过 `FunctionRegistry::LookupFunction()` 查找已注册的实现
5. 如果找到,构造 `FuncExpr` 节点;否则返回 nullptr(走回退执行路径)

```cpp
// === 新增: REVERSE 函数实现 ===
extern "C" DLLEXPORT char* ReverseString(
    const char* str,
    int32_t strLen,
    bool isNull,
    int32_t* outLen)
{
    if (isNull || strLen == 0) {
        *outLen = 0;
        return nullptr;  // 由框架处理null/空字符串
    }

    // 分配输出缓冲区 (使用Arena分配器避免内存泄漏)
    auto* result = reinterpret_cast<char*>(
        omniruntime::ArenaAllocatorMalloc(strLen));
    if (result == nullptr) {
        *outLen = 0;
        return nullptr;
    }

    // UTF-8 安全反转: 按码点反转
    int32_t srcOffset = 0;
    int32_t dstOffset = strLen;
    while (srcOffset < strLen) {
        int32_t cpLen = omniruntime::Utf8Util::CodePointByteLength(
            static_cast<uint8_t>(str[srcOffset]));
        dstOffset -= cpLen;
        std::memcpy(result + dstOffset, str + srcOffset, cpLen);
        srcOffset += cpLen;
    }
    *outLen = strLen;
    return result;
}
```

**关键要点**:

- 字符串参数: `(const char* str, int32_t strLen, bool isNull)`
- 字符串返回值: 返回 `char*`,末尾参数 `int32_t* outLen` 指定输出长度
- 使用 `ArenaAllocatorMalloc()` 分配内存,框架在批次结束后自动回收
- 使用 `DLLEXPORT` 宏确保符号导出

```cpp
    virtual void Update(Accumulator* acc, VectorBatch* input, int32_t rowIdx) = 0;
```

```cpp
class StddevPopAggregator : public Aggregator {
public:
    void Init(Accumulator* acc) override {
        acc->SetLong(0, 0);   // count
        acc->SetDouble(1, 0.0); // sum
        acc->SetDouble(2, 0.0); // sum_of_squares
    }

    void Update(Accumulator* acc, VectorBatch* input, int32_t rowIdx) override {
        auto* col = input->GetVector(0);  // 第一列为聚合列
        if (col->IsNull(rowIdx)) return;

        double value = col->GetDouble(rowIdx);
        int64_t count = acc->GetLong(0) + 1;
        double sum = acc->GetDouble(1) + value;
        double sumSq = acc->GetDouble(2) + value * value;

        acc->SetLong(0, count);
        acc->SetDouble(1, sum);
        acc->SetDouble(2, sumSq);
    }

    void GetResult(Accumulator* acc, Vector* output, int32_t rowIdx) override {
        int64_t count = acc->GetLong(0);
        if (count <= 1) {
            output->SetNull(rowIdx);
            return;
        }
        double sum = acc->GetDouble(1);
        double sumSq = acc->GetDouble(2);
        double mean = sum / count;
        double variance = sumSq / count - mean * mean;
        output->SetDouble(rowIdx, std::sqrt(variance));
    }

    // Merge 用于多阶段聚合
    void Merge(Accumulator* dst, Accumulator* src) override {
        dst->SetLong(0, dst->GetLong(0) + src->GetLong(0));
        dst->SetDouble(1, dst->GetDouble(1) + src->GetDouble(1));
        dst->SetDouble(2, dst->GetDouble(2) + src->GetDouble(2));
    }
};
```

### Step 1:Flink SQL 侧注册(概念说明)

> 注:此步骤在 Flink/Calcite 端完成,本文仅做概念说明,详细实现请参考 Flink 端文档。

在 Flink Calcite 中注册 `JSON_VALUE` SQL 函数后,Flink 优化器生成类似以下 JSON 协议:

```json
{
    "exprType": "FUNC",
    "function_name": "json_value",
    "returnType": 15,
    "width": 2147483647,
```

### Step 2:JSON 反序列化(JSONParser)

入口在 `jsonparser.cpp` 的 `ParseJSONFunc()`:

```cpp
// jsonparser.cpp:563
Expr *JSONParser::ParseJSONFunc(const Json &jsonExpr)
{
    string funcName = jsonExpr["function_name"];
    auto retTypeId = static_cast<DataTypeId>(jsonExpr["returnType"].get<int32_t>());
    std::vector<Expr *> args;
    DataTypePtr retType;

    if (funcName == "json_value") {
        // json_value 特殊参数处理: ON EMPTY/ERROR/DEFAULT 行为
        if (!BuildJsonValueArguments(jsonExpr, &args)) {
            Expr::DeleteExprs(args);
            return nullptr;
        }
    } else {
        // 普通函数: 直接解析 arguments 数组
        for (const auto &item : jsonExpr["arguments"].items()) {
            Expr *arg = ParseJSON(item.value());
            // ...
            args.push_back(arg);
        }
    }

    // 构造返回类型
    if (TypeUtil::IsStringType(retTypeId)) {
        width = jsonExpr.contains("width") ? jsonExpr["width"].get<int32_t>() : width;
        retType = std::make_shared<VarcharDataType>(width);
    } else if (TypeUtil::IsDecimalType(retTypeId)) {
        // ...
    } else {
        retType = std::make_shared<DataType>(retTypeId);
    }

    // 查找注册函数
    auto signature = FunctionSignature(funcName, argTypes, retTypeId);
    auto function = FunctionRegistry::LookupFunction(&signature);
    if (function != nullptr) {
        return new FuncExpr(funcName, args, std::move(retType), function);
    }
    // 未找到 → 返回 nullptr(走回退路径)
    return nullptr;
}
```

**json_value 特殊参数构建** — `BuildJsonValueArguments()`:

该函数将 JSON 中的 `arguments`(原始 2 个参数:json 字符串 + path 字符串)扩展为 **6 个参数**:

| 参数索引 | 含义                                      | 类型         |
| -------- | ----------------------------------------- | ------------ |
| 0        | json 字符串                               | VARCHAR      |
| 1        | json path                                 | VARCHAR/CHAR |
| 2        | emptyBehavior(0=NULL, 1=ERROR, 2=DEFAULT) | INT          |
| 3        | defaultOnEmpty 表达式                     | VARCHAR      |
| 4        | errorBehavior(0=NULL, 1=ERROR, 2=DEFAULT) | INT          |
| 5        | defaultOnError 表达式                     | VARCHAR      |

```cpp
// jsonparser.cpp:530
bool BuildJsonValueArguments(const Json &jsonExpr, std::vector<Expr *> *args)
{
    // 1. 解析原始 2 个参数
    for (const auto &item : jsonExpr["arguments"].items()) {
        Expr *arg = JSONParser::ParseJSON(item.value());
        if (arg != nullptr) args->push_back(arg);
        else return false;
    }

    // 2. 解析 emptyBehavior 和 defaultOnEmpty
    int32_t emptyBehavior = JSON_VALUE_NULL_BEHAVIOR;  // default: NULL
    Expr *defaultOnEmpty = nullptr;
    ParseJsonValueBehavior(jsonExpr, "emptyBehavior", &emptyBehavior, &defaultOnEmpty);

    // 3. 解析 errorBehavior 和 defaultOnError
    int32_t errorBehavior = JSON_VALUE_NULL_BEHAVIOR;
    Expr *defaultOnError = nullptr;
    ParseJsonValueBehavior(jsonExpr, "errorBehavior", &errorBehavior, &defaultOnError);

    // 4. 追加到参数列表(总共 6 个参数)
    args->push_back(CreateJsonValueBehaviorLiteral(emptyBehavior));
    args->push_back(defaultOnEmpty);
    args->push_back(CreateJsonValueBehaviorLiteral(errorBehavior));
    args->push_back(defaultOnError);
    return true;
}
```

### 10.3 UT 场景矩阵（按仓库：何时写、写哪个）

UT 按「非平凡逻辑落在哪个仓库」分两侧,各测各的、直驱被测单元、互不重复:

| 仓库 | UT 类型 | 测什么(非平凡逻辑) | 直驱入口 | 何时写 | 运行环境 |
|------|---------|---------------------|----------|--------|----------|
| OmniOperator(C++) | `core/test/vectorization/<Fn>Test.cpp` | 向量化函数 `call()` 语义(三值/边界/类型分派) | `VectorFunction::Apply`(非 ExprEval) | 每个新向量化函数**必写** | 鲲鹏远端(`operator_test`) |
| OmniAdaptor(Java) | `omni-table-planner/src/test/java/.../RexNodeUtilXxxTest.java` | `RexCall→JSON` 翻译(新 exprType/嵌套构建/别名/特殊参数/CAST) | `RexNodeUtil.buildJsonMap`(直驱,不 mock) | **仅翻译非平凡时写** | Windows 本地 `mvn test` |
| 端到端(e2e) | `flink-test/test/<name>/` | 接线 + 决策链 + native==vanilla 逐行一致 | `run_local.sh`(native vs vanilla) | 每个表达式**必跑** | 鲲鹏远端集群 |

**判定原则:**
- **平凡翻译不写 Java UT**:新 FUNCTION case 是邻近 case 的复制(仅 `function_name`/参数个数不同、无逻辑分叉),靠 e2e 覆盖接线(反例:LEFT/RIGHT 复制 LOWER,未写 Java UT)。
- **非平凡翻译必写 Java UT**:新 exprType 分支、递归/嵌套 JSON 构建(COALESCE N 参展平)、别名映射须产出特定形态(IFNULL→COALESCE)、特殊参数扩展(json_value 2→6 参)、CAST 注入/类型矩阵分叉(正例:NOT 运算 `RexNodeUtilNotTest.java`,commit `d920300c`)。
- **Java UT 可本地跑**(`mvn test`,无需鲲鹏)是其相对 C++ UT 的优势——翻译层 bug 本地秒级定位,不必等远端 e2e。
- **三者互补不替代**:Java UT 不验 C++ 语义,C++ UT 不验翻译接线,均不替代 e2e 的 native==vanilla。

## 12. C 函数参数命名规范

row JIT 路径(`codegen/functions/`)的所有 C 函数需遵循以下规范:

### 12.1 参数三元组

- **输入参数**:`(type *value, int32_t len, bool isNull)` 三元组
  - VARCHAR/CHAR 类型:额外携带 `int32_t width` 作为第 2 个参数(即四元组 `(char*, int32_t width, int32_t len, bool)`)
- **ExecutionContext**:首参数 `int64_t contextPtr`,仅当注册时 `setExecutionContext=true`
- **输出参数**:`(bool *outIsNull, int32_t *outLen)` 作为最后两个参数
- **返回值**:`const char*` 指向输出缓冲区

### 12.2 各类型参数形态(排错速查)

- VARCHAR 参数:`(char*, int32_t len, bool)`
- CHAR 参数:`(char*, int32_t width, int32_t len, bool)`
- 字符串返回值:返回 `char*`/`const char*`,末尾带 `int32_t* outLen`
- DECIMAL128 参数:`(int64_t high64, uint64_t low64)`

### 12.3 内存分配

- 使用 `ArenaAllocatorMalloc()` 分配临时内存,框架在批次结束后自动回收
- **不要**使用 `new`/`malloc`(会导致内存泄漏)
- 使用 `DLLEXPORT` 宏确保符号导出

## 13. NullableResultType 处理策略

`Function` 注册时的 `NullableResultType` 决定 NULL 处理策略:

```cpp
enum NullableResultType {
    INPUT_DATA,                           // 不处理 NULL
    INPUT_DATA_AND_NULL,                  // 输入数据含 NULL
    INPUT_DATA_AND_OVERFLOW_NULL,         // 输入数据 + 溢出时返回 NULL
    INPUT_DATA_AND_NULL_AND_RETURN_NULL,  // 输入可为 NULL 且返回可为 NULL
    DEFAULT                               // 默认
};
```

| 模式                                    | 行为                           | 适用场景                            |
| --------------------------------------- | ------------------------------ | ----------------------------------- |
| `INPUT_DATA`                          | null 输入自动短路,函数不执行   | 大多数标量函数(如`reverse`)       |
| `INPUT_DATA_AND_NULL`                 | 传入 null 位图,函数需处理 null | 需要感知 null 的函数                |
| `INPUT_DATA_AND_OVERFLOW_NULL`        | 溢出感知模式                   | Decimal 运算                        |
| `INPUT_DATA_AND_NULL_AND_RETURN_NULL` | 输入可为 NULL 且返回可为 NULL  | 输入输出均可 null(如`json_value`) |

> 排错:`INPUT_DATA` 模式下 null 输入不会调用函数;若函数需感知 null,改用 `INPUT_DATA_AND_NULL*`。

## 14. Function 构造与注册机制

### 14.1 Function 结构体

每个注册的函数通过 `Function` 类描述:

```cpp
// function.h
class Function {
public:
    Function(void *address,                    // C 函数指针(void* 转换)
             const std::string &name,          // 函数名(与 Flink 侧一致)
             const std::vector<std::string> &aliases,  // 别名列表
             const vector<DataTypeId> &paramTypes,     // 参数类型列表
             const DataTypeId &retType,                // 返回类型
             NullableResultType nullableType,          // NULL 处理策略(见 §13)
             bool setExecutionContext);                // 是否传递 ExecutionContext(首参数)
};
```

| 参数                    | 值示例                   | 说明                                                                  |
| ----------------------- | ------------------------ | --------------------------------------------------------------------- |
| `address`             | `ReverseString` 的指针 | 实际调用的 C++ 函数                                                   |
| `name`                | `"reverse"`            | 与 JSON 中`function_name` 一致(大小写敏感)                          |
| `aliases`             | `{}`                   | 别名,如`{"rev"}` 则也可用 `rev` 调用                              |
| `paramTypes`          | `{OMNI_VARCHAR}`       | 入参类型列表                                                          |
| `retType`             | `OMNI_VARCHAR`         | 返回类型                                                              |
| `nullableType`        | `INPUT_DATA`           | NULL 处理策略(见 §13)                                                |
| `setExecutionContext` | `false`/`true`       | true 时首参为`int64_t contextPtr`(如 `json_value` 用于 JSON 缓存) |

### 14.2 注册器列表

在 `func_registry.cpp` 中,`FunctionRegistry::GetRowFunctionRegistries()` 收集所有 domain 的注册器:

```cpp
vector<unique_ptr<BaseFunctionRegistry>> FunctionRegistry::GetRowFunctionRegistries()
{
    vector<unique_ptr<BaseFunctionRegistry>> registries;
    registries.push_back(make_unique<ContextFunctionRegistry>());
    registries.push_back(make_unique<DecimalFunctionRegistry>());
    registries.push_back(make_unique<DictionaryFunctionRegistry>());
    registries.push_back(make_unique<MathFunctionRegistry>());
    registries.push_back(make_unique<HashFunctionRegistry>());
    registries.push_back(make_unique<MightContainFunctionRegistry>());
    registries.push_back(make_unique<VarcharVectorFunctionRegistry>());
    registries.push_back(make_unique<HiveUdfRegistry>());
    registries.push_back(make_unique<StringFunctionRegistry>());   // json_value / reverse 在这个注册器中
    registries.push_back(make_unique<DateTimeFunctionRegistry>());
    registries.push_back(make_unique<JsonFunctionRegistry>());
    return registries;
}
```

### 14.3 函数查找流程

`FunctionRegistry::InitializeRowFunc()` 的初始化流程:

```
InitializeRowFunc()
  → GetRowFunctionRegistries() 获取所有注册器
  → 遍历每个注册器,调用 GetFunctions()
  → 收集所有 Function 对象
  → 遍历 Function,按 FunctionSignature(funcName, argTypes, retType) 建立哈希索引
  → 后续查询时根据签名精确匹配
```

> 排错:`Function not supported: <name>` 多因注册名 ≠ `function_name`(大小写)/ 签名不匹配 / `returnType` DataTypeId 错 / VARCHAR 漏 width。

# 第六部分:排错与调试

## 15. 排错与调试

### 15.1 表达式未进入 Native 路径

**症状**:SQL 执行正确但日志中无 `[OmniStream]` 输出

**排查**:

```bash
# 1. 检查 JobGraph 中是否有 Omni 标记
grep "OmniGraphOverride" <flink_home>/log/flink-*.log

# 2. 检查 ValidateCalcOPStrategy 是否拒绝
grep "OmniGraphOverride" <flink_home>/log/flink-*.log | grep "INVALID\|unsupported"
```

**常见原因**:

- `specialOperatorMap` 中未添加函数名映射
- 当前参数类型不在 `is_supported_type` 正向列表中
- `ValidateCalcOPStrategy` 校验失败

### 15.2 JSONParser 解析失败

**症状**:`[OmniOperator] Function not supported: <name>`

**排查**:

- 确认 `function_name` 拼写与 C++ 注册名完全一致(**大小写敏感**)
- 确认 `FuncExpr` 的 `paramTypes` 和 `retType` 与 `FunctionSignature` 匹配
- 检查 `returnType` 整数 ID 是否正确

### 15.3 CodeGen 编译失败

**症状**:JIT 编译报错或段错误

**排查**:

- 检查 C++ 函数签名:参数个数和类型是否与 `Function` 注册一致
- VARCHAR 参数:`(char*, int32_t, bool)`
- CHAR 参数:`(char*, int32_t width, int32_t len, bool)`
- 字符串返回值:返回 `char*`,末尾带 `int32_t* outLen`
- DECIMAL128 参数:`(int64_t high64, uint64_t low64)`

### 15.4 运行时结果异常

**症状**:结果为空或错误

**排查**:

1. 检查 `NULL` 处理:`INPUT_DATA` 模式下,null 输入不会调用函数
2. 检查内存分配:使用 `ArenaAllocatorMalloc()` 而非 `new`/`malloc`
3. 检查 `DLLEXPORT` 宏是否正确导出符号
4. 添加调试日志:

```cpp
#ifdef OMNIDEBUG
LogInfo("reverse(%s, len=%d, isNull=%d) → %s, outLen=%d",
    str, strLen, isNull, result, *outLen);
#endif
```
